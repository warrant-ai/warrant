# Instructions for coding agents

This file is for a coding agent working in this repository, whether on its own or driven by a person. `CONTRIBUTING.md` has the full rules; this is the operational subset.

## What this repository is

Two SDKs that must produce identical bytes (`python/`, `js/`), one JSON Schema (`schema/`), one specification (`spec/adr-0.2.md`), and the files that define correctness for both SDKs (`conformance/`). A change is right when the gates say so, not when it looks right.

## Commands, in order

```
cd python && python -m venv .venv && .venv/bin/pip install -e ".[dev]" && .venv/bin/pytest
cd js && npm ci && npm test && npm run typecheck
python scripts/differential.py --seed 7 --count 500
```

Green means: pytest reports no failures (skips for PostgreSQL and live vendors are expected without credentials and are printed with their reasons), `node --test` reports no failures, `tsc` reports no errors, and the differential script exits 0. If you changed the schema, also run `scripts/sync-schema.sh` and confirm `git diff` shows the three copies changed together.

## Do not

- Edit any file under `conformance/` by hand. They are generated by `scripts/gen_adr_vectors.py` and `scripts/gen_admissibility_cases.py`. If a vector has to change, the specification and the changelog change in the same commit, and you say why.
- Edit `python/src/warrant/schema/decision-record.v0.json` or `js/schema/decision-record.v0.json` directly. Edit `schema/` and run `scripts/sync-schema.sh`.
- Change the record path (`hashing`, `signing`, `merkle`, `admissibility`, the seal logic in `store`/`client`) in one SDK without the other.
- Set `TYPESAFE_API_KEY`, `WARRANT_LAYA_LIVE` or any live-vendor variable. Those tests spend money or download model weights.
- Add a dependency to the base package. Python's base dependency is `jsonschema`; JavaScript's are `ajv` and `ajv-formats`. New dependencies go behind an optional extra or an optional peer dependency.
- Record an exception message anywhere a record is written. Only the class name is recorded.
- Add code that updates or deletes a sealed record.
- Reference `docs/`. It is listed in `.gitignore` and is not part of the repository.
- Touch `release.yml` or add any publishing step.

## When the task is a port to another language

Make the vector groups in `conformance/adr-vectors.json` pass in this order: `canonical`, `salted`, `seal` and its three variants, `key`, `merkle` and `checkpoint_message`. Each group is a list or object of inputs and expected outputs; load the file, loop, compare bytes. Do not derive expected values from the Python code; derive them from the file and the spec, and report a mismatch between the two as a finding instead of resolving it yourself.

## What to write in the pull request

Use the template. Fill every field. The two that matter most are "what I ran" (the exact commands and their final lines) and "what I could not verify". A pull request that says it could not run the PostgreSQL tests is fine. One that implies it ran them when it did not is not.

State that an agent wrote the change and name the model. The reviewer reads agent-written changes for three things in particular: fields or behaviours that were assumed rather than read from the schema or spec; tests that assert what the implementation does rather than what the spec says; and changes that make a failing test pass by weakening the test.
